### 切年份刷新（v1.8.2 核心）

```
_switch_year():
    点「另一个年份」 → 等 YEAR_SWITCH_SETTLE_SECONDS(0.25s)
    → 点回「目标年份」 → 等待
```

用途（全部替换了原来的「back 回列表 → 点商品 → 等整页重载」）：

| 场景 | 现在的动作 |
|---|---|
| 售罄复核 | 切年份往返 → 再看一眼，第二次仍售罄才结束 |
| 补货中~xx:xx | 切年份 → 详情内等到点 → 点回目标年份 → 连读两次确认 → 点 |
| 连点达阈值 | 切年份往返 → 重新确认数量 → 继续点 |
| 预热 | 切一次年份（不再离开详情页） |
| 到点进入 | 详情内点回目标年份（不再从列表点商品） |

两个必须记住的副作用：
1. **切 SKU 会把数量重置成 2**，所以切完一律回 `SELECT_QTY` 复核（已是 6 就跳过）。
2. 切年份不可用（档案缺年份格 / 页面未渲染）时，自动退回 `_back_to_list` + `ENTER_PRODUCT` 老路径。

`_stuck_recover`（3 秒无进展的本地恢复）同样先试切年份：成功就留在详情页回
`SELECT_QTY` 重新确认；只有切不动时才 `back`。

## 十七、按钮翻转探针（App 内诊断）

回答一个问题：**停在详情页不动，整点到了按钮会不会自己从「xx:xx投放」变成「立即购买」？**
这决定第一击能不能提前就位（能提前 → 省 2~6 秒；不能 → 保持"列表等、整点进"）。

| 逻辑 | 文件 | 函数 |
|---|---|---|
| 入口（界面按钮） | app_ui.py | `probe_btn` / `set_probe_running` |
| 启动/停止 | main.py | `_on_probe_pressed` |
| 导航到详情 | flip_probe.py | `_navigate_to_detail`（复用 FlowCore 的页面判定与点击） |
| 取色采样 | flip_probe.py | `_sample` / `_sample_region`（`max_red_in_regions`，一次截图一次采样） |
| 翻转判定 | flip_probe.py | `_redness` + `YEAR_RED_MIN` |
| 结果落盘 | flip_probe.py | `_write_result`（`flip_probe_*.txt` / `.csv`，写在日志目录） |

要点：
- 目标时刻前 `PROBE_LEAD_SECONDS + 30` 秒才开始导航，避免长时间停在详情页吃风控；
- 一个样本都没采到（导航超窗）时结论明确写"本次无效"，不会误报成"按钮没翻转"；
- 不校验卡密、不扣次、不下单。
